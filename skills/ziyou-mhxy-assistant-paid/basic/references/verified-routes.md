# 可核对的离线路线：修炼道具、降修、宝石资格与星辉石

规则版本：`pc-time-routes-2026-10-06`。核对日期：2026-10-06。适用梦幻西游电脑版时间服；不适用于手游、畅玩服或其他游戏。这里只给资源算术与条件检查，不给战斗伤害、胜率或自动操作。

每次返回 `ruleIds` 和官方 `citations`。完整的规则状态、官方URL、页面栏目、日期和缺口在 [`rule-sources.json`](rule-sources.json)。`verified` 表示明确的官方来源；`partial` 表示只核实部分；`unsupported` 表示没有把未知信息补成公式。核对日期不是“已覆盖全部2026版本”的保证。部分旧介绍存在日期/上限陈旧情况，见下文。

所有算法为独立编写；仅采用公开游戏规则和数值事实。没有复制官网工具箱的程序或界面素材。运行时不联网、不抓取价格、不读游戏客户端、不调用外部API。官方工具箱静态数据只在本次规则核对时用于核实召唤兽修炼经验事实。

## 入口与输出约定

命令行在包根目录运行，Python标准库即可：

```sh
python -X utf8 scripts/routes.py examples/routes-gold_pill.json --kind gold_pill
python -X utf8 scripts/routes.py examples/routes-pet_fruit.json --kind pet_fruit
python -X utf8 scripts/routes.py examples/routes-cap_route.json --kind cap_route --output my-cap-result.json
python -X utf8 scripts/routes.py examples/routes-gem_eligibility.json --kind gem_eligibility
python -X utf8 scripts/routes.py examples/routes-star_gem.json --kind star_gem
python -X utf8 scripts/routes.py --help
```

`--output` 只能新建文件，存在即报错，不覆盖输入或旧结果。输入读取沿用 `resources.py` 的严格UTF-8 JSON处理：普通文件、不允许符号链接，最大1MiB，拒绝重复JSON字段、浮点、指数、布尔值、超长整数。整数接受数值或十进制字符串，大于JS安全整数的数字请用字符串。各计算器拒绝未知字段。返回数值一律字符串，未知金额为 `null`。精确有理数以 `分子/分母` 字符串输出，不做隐式浮点取整。

Python API：

```python
from scripts.routes import (
    cultivation_items, pet_cultivation, cap_route, gem_feasibility, star_gems
)
```

`CALCULATORS` 映射 CLI 名称到对应函数：

| CLI kind | Python函数 | 支持范围 |
| --- | --- | --- |
| gold_pill | cultivation_items | 手工确认每颗实际XP的金丹数量、余量、纯路线金额比较和临界单价 |
| pet_fruit | pet_cultivation | 0至25级召唤兽修炼经验与150XP/果数量预算；资格单独标识 |
| cap_route | cap_route | 四修飞升时选择与已飞升后逐次降修的最少普通修炼资源路线 |
| gem_eligibility | gem_feasibility | 普通宝石部位、两种类型、逐级、装备上限、精致/无级别例外 |
| star_gem | star_gems | 指定等级、指定颗数的星辉石成品材料下限，含2024高等级额外配方 |

这是独立于原 `resources.py` 的扩展，不改变旧普通修炼/宝石算术。由宿主调用Python接口并解释结果。

### 人工报价格式

`gold_pill`、`pet_fruit`、`star_gem` 可选 `quote`。不填则金额未知；明确填0才表示零价。报价仅允许游戏币“两”，不会擅自换算人民币。

`quote` 必须包含以下全部字段：

- `unitPrice`：所选道具一颗的游戏币单价，非负整数
- `server`：报价所在服务器
- `date`：报价观察/成交日期，有效 `YYYY-MM-DD`，不得晚于 `asOf`；不以规则核对日期限制后续正常价格更新
- `kind`：`asking`（挂牌价）、`sold`（历史成交）、`user_quote`（用户人工报价）或 `estimate`（估计）
- `currency`：固定为 `两`
- `source`：用户手工记录的来源，例如游戏内摊位观察及道具品质/等级；文本不触发访问

可选 `asOf` 是价格核对日期（默认运行时UTC今天），`maxAgeDays` 是允许的最长年龄（默认7，0表示仅当天）。返回 `ageDays`、`freshness`、`stale` 和解释警告；年龄等于期限仍算新鲜，大于期限为过期。价格可晚于2026-10-06规则核对日，但不意味着游戏规则已重新验证。

金丹报价必须对应输入的同品质、同实际XP道具；星辉石报价是目标等级成品一颗，不是一级材料报价。工具不能验证玩家是否准确抄录了摊位价格。示例文件不提供市场价格；测试中合成的价格明确标为测试数据。

## 九转金丹：有用的条件预算，品质换算不冒充官方规则

本次没有找到能独立核实“品质÷2”及奇数品质取整的官方出版资料，自动品质→XP换算仍不支持。网上玩家答案可表达需求，不能充当官方依据。

必填字段：`type`、`currentLevel`、`targetLevel`、`currentProgressXp`、`confirmedCap`、`quality`。`type` 仅支持 `attack`、`spell`、`defense`、`anti_spell`，不支持猎术。等级范围0至25，目标不能低于当前或超过游戏内已确认上限。本级进度必须小于升下一级所需XP；已到上限时填0。

真正得到道具预算还需两个字段：

- `confirmedItemXp`：用户从游戏内确认的每颗实际XP，可为整数或正有理数字符串
- `itemXpEvidence`：确认依据；这只是用户输入，不能自动变成公开已验证规则

缺少确认XP时返回 `status=unsupported`，列出缺字段，仍给普通修炼预算，不把 `quality` 代入某个未经验证的公式。`quality` 仅描述所选金丹。手工XP齐全时状态为 `conditional_manual_xp`，不宣称该角色已满足道具资格。

所需经验依据[官方人物修炼](https://xyq.163.com/introduce/zd008.html)，累计到目标等级后扣除本级进度。道具颗数为 `ceil(剩余XP/每颗实际XP)`，余量为 `颗数×单颗XP−剩余XP`。所有余量只是算术结果，尤其封顶时是否保留没有被核实。

与普通修炼对照时，`breakEvenUnitPriceLiang = 普通路线实际购次费用 / 道具向上取整颗数`。不需要价格也能输出此精确临界价；无需升级时为 `null`。有同服人工报价后比较全普通/全道具两条纯路线，不声称优化了混合采购或时间成本。过期时 `cheaperRoute` 与 `savingsLiang` 留空，条件算术单独保留在 `conditionalPriceComparison`；金额同时带过期警告。新鲜也不保证货源或成交：挂牌、已售、人工报价、估计口径始终随结果呈现。

手算例：0→9需5190XP。若用户确认该金丹一颗实际50XP，则需104颗，算术余量10XP。攻修普通路线15,570,000两，临界单价为15,570,000/104两。不能用5190/50的非整数颗数直接算购买总价。0→1已有149XP时只缺1XP，普通仍买一次10XP；50XP/颗的金丹仍需一颗。

## 修炼果：经验和可用资格分开

必填字段：`type`、`currentLevel`、`targetLevel`、`currentProgressXp`、`confirmedCap`。四种类型和区间校验与上面一致。

可选：`characterLevel`（0至175）、`fruitEligibility`（`confirmed`/`unknown`/`ineligible`，默认未知）、`quote`。`fruitEligibility` 是用户对游戏内当前可用性的确认，工具不能据此宣称公开规则已补齐。

[官方召唤兽修炼介绍](https://xyq.163.com/introduce/zhs010.html)核实每颗果150XP。[官方工具箱](https://xyq.163.com/tools/index.html)及其直接引用的[公开静态数据](https://xyq.res.netease.com/pc/zt/20220406145527/pkg/app_3b629e4.js)提供0至25累计修炼经验；各级差分与人物修炼XP公式一致。0→20合计37,200XP，正好248果；0→25合计67,750XP，452果、算术余量50XP。

重要限制：旧官方介绍写最高20，而官网工具箱包含25级数据。这不能用于自动判断某个账号已经解锁25。必须输入游戏内实际确认上限。官方介绍的≥65级是任务/秘传任务条件；工具箱的 `max(65,目标×5+20)` 仅作为任务等级参考返回，不能直接外推成所有道具使用条件。每日可吃数量、特殊上限解锁和封顶余量保留没有独立核实，因此不自动估算吃完天数。资格未知时仍可得预算，但状态明确为 `eligibility_unknown`。

## 飞升与后续降修：不能混为一谈

必填：`type`、`stage`、`currentLevel`、`currentProgressXp`、`confirmedCap`、`targetLevel`、`characterLevel`。`stage` 为 `before`（尚未飞升，规划包含一次飞升）或 `after`（已经飞升）。只支持人物四修。飞升前只接受已确认20上限；已飞升接受20至25上限。`characterLevel` 是角色当前等级，不是修炼等级。

[官方角色飞升](https://xyq.163.com/introduce/zd009.html)明确给出：

| 飞升前修炼 | 选择降修后的修炼 | 新上限 |
| --- | --- | --- |
| 13 | 12 | 21 |
| 14 | 12 | 22 |
| 15 | 13 | 22 |
| 16 | 13 | 23 |
| 17 | 14 | 23 |
| 18 | 14 | 24 |
| 19 | 15 | 24 |
| 20 | 15 | 25 |

12及以下飞升不降。猎术不适用。已经飞升以后，上限未到25且“上限−当前等级<2”时，降一级修炼、提升一级上限。这与飞升瞬间上表不同。

算法在状态 `(当前修炼, 上限, 飞升阶段)` 上求最短资源路径；每次普通点修为带XP权重的边，飞升保留、飞升降修、后续降修为改变状态的边。它枚举可行选择，不硬编码“18飞永远最省”，因为已投入的修炼是沉没成本，目标和当前状态也会改变答案。

输出包括每一步前后等级/上限、追加XP、普通修炼购次、两、资材、门槛、与“满上限才降修”受限策略相比的差额。优化目标是最少追加普通修炼XP；在同项目固定单价下也同时最少两及资材。不会优化金丹混用，不包含其他账号养成费用。

手算校验：已飞升21修、上限22、目标25，尽早降修路线是：

1. 21→20，上限22→23；点回21、22
2. 22→21，上限23→24；点回22、23
3. 23→22，上限24→25；点至23、24、25

新增XP为5150+5610+5610+6090+6090+6590+7110=42,250；攻/法修126,750,000两。满上限再降需43,690XP、131,070,000两，差4,320,000两。这里不使用飞升前18修建议回答“已经飞升”的问题。

另一个反例：从0修开始规划至25，最少新增XP路线选择18飞降14，再在23修降一级，合计87,200XP；已在19修的角色规划未来花费时，先到20飞反而更少，追加54,810XP。这说明要基于当前状态重算。

资格与未知信息：

- 飞升任务要求角色≥135、任意6项师门技能≥130，并实际完成任务
- 飞升角色等级减15；路线输出飞升前/后点修的最低角色等级。现等级不够时返回 `requires_character_levels`，不会算成当前立即可执行
- 普通点修还需入帮>14天、项目开放、累计帮贡>实际最高点修等级×150、资材足够；帮贡不在普通模式扣除
- 角色/技能升级、飞升任务、时间与机会成本不在最短费用里，故这是“普通修炼部分资源最少”，不是整账号所有成本最少
- 官网未说明非零本级XP在降修中怎样处理。若规划涉及飞升或突破当前上限且输入进度非零，返回 `unsupported`，绝不暗定清零/保留。零进度时每次完整升级所需XP为10倍数，普通点修可以走到精确零进度边界再降
- 已飞升且目标不超过当前上限时可扣除非零进度，最后普通购次仍向上取整

## 普通宝石操作与资格检查

镶嵌地点、实际步骤、合成风险和两类技能问题分开回答，见grounded-player-guidance.md与grounded-mechanics.md的gem_operations。官方宝石旧页明确铁匠铺放装备+宝石逐级镶嵌；普通宝石合成另按2024-05-21全服的目标等级、附加料、宝石工艺门槛处理：12–20级单次必成，2–11级精确概率未核。直接镶嵌是否失败及明确技能门槛未由该页独立确认，输出未知，不以合成机制替代答案。此操作分项复核日2026-10-07，不刷新本文件其他规则核验日。

## 普通宝石资格检查

必填：`gemType`、`slot`、`equipmentLevel`、`currentForge`、`targetForge`、`existingGemTypes`、`effects`。

- `gemType` 使用原 `resources.py` 的八个ID：radiance/sun/moon/black/agate/relic/mystery/jade
- `slot`：武器/头盔/铠甲/腰带/鞋子/项链
- `equipmentLevel`：原始装备要求等级（0至160，10的倍数）；简易80装备仍填80，不填75
- `existingGemTypes`：当前已镶嵌的类型ID列表，最多2种，不重复；0锻填空列表，非0锻不可省略已有类型
- `effects`：精致/无级别限制/简易组成的不重复列表，普通装备填空列表
- `providedGrades` 可选：用户打算提供的有序宝石等级列表；有此字段则逐项核对是否刚好为当前+1直到目标

依据[官方宝石](https://xyq.163.com/introduce/dj008.html)，查部位、每件最多两种、逐级禁止跳级。普通上限为原装备等级÷10；[官网工具箱精致条目](https://xyq.163.com/tools/index.html)核实精致加1。无级别不受装备等级/10限制，但本版只核验到20锻，不宣称全局无限级。

80级头盔、7锻月亮、精致，提升至9需8/9级月亮各一颗，可行；没有精致则9锻超限。只带9级一颗不能跳过8级。原有两类不同宝石时不能新加第三类。不可行时 `rawStatDelta` 为 `null`，避免把不成立的操作显示成收益。

通过资格检查后，价格/全部新增锻数材料可交给原 `resources.gems()` 预算。八种宝石的增量只是原始装备属性，不是最终面板或实战效果。

## 星辉石：3合1还不够，高等级有额外材料

必填：`targetGrade`（1至11）、`quantity`（正整数）；可选 `craftSkill`（0至7）、`quote`。本函数计算“目标等级成品若干颗”，不把最高级单颗材料量冒充灵饰整个逐级镶嵌总花费。

[官方灵饰](https://xyq.163.com/introduce/2014/11/6/5015_474275.html)核实3颗同级合成1颗高一级；[2024-05-21调整](https://xyq.163.com/news/20240520/4999_1156134.html)对9至11增加材料：

| 目标等级 | 3颗前一级之外额外需要 | 单颗无失败一级材料下限 |
| --- | --- | --- |
| 8 | 无 | 2187 |
| 9 | 5级1颗 | 6642 |
| 10 | 6级、7级各1颗 | 20898 |
| 11 | 9级1颗 | 69336 |

递推 `F(1)=1`，`F(g)=3F(g−1)+额外材料的F之和`。9至11级这次合成必定成功，前置低级合成损失仍未计入。工艺要求：2级需4，3至5需5，6至7需6，8至11需7；未输入工艺等级时输出 `skill_unknown`。直接购买目标成品的报价总价与合成材料下限分开显示。

未独立核实星辉石逐属性增量，`rawStatDelta` 固定 `null`。不编造气血、伤害、速度加成；不推导灵饰特殊特效或12级以上配方。一般灵饰镶嵌上限为等级÷10的官方条件仅作为提醒，当前函数并非灵饰镶嵌资格检查器。

## 尚不支持

- 自动九转金丹品质→XP及奇数品质取整
- 非零进度飞升/降修重置行为
- 修炼果每日用量、特殊上限解锁和资格的自动推断
- 星辉石逐属性精确增量、12级及以上规则
- 人物升级、师门技能完整费用表；本版未完成独立来源核验
- 市场价格抓取、人民币换算、战斗伤害/治疗/存活公式

## 2.1.0-rc2：人物穿戴等级检查

gem_eligibility新增可选characterLevel（已知时由宿主填入）。[官方装备特效](https://xyq.163.com/introduce/jn002.html)已核实：简易使人物穿戴等级要求降低5级；无级别不限制人物穿戴等级。无级别的宝石上限规则与这个人物等级规则是两个判断；简易仍不改变输入的原装备等级或普通锻数上限。

返回minimumCharacterLevel、characterLevelEligible与wearingScope。未给人物等级时该资格为null，不能从镶嵌eligible推出角色可穿。给了等级却不足时整体不再显示可用于本角色的升级收益。尚不核对武器类型、角色造型、性别、门派、种族等其他装备条件。
