# 新增资产分析：固定服务目录与免费资料流程

本指引用于已有资产自动分配与角色组合服务，付款交由支付宝官方支付技能完成。玩家说普通中文，宿主整理其已提供事实；不要要求玩家写 JSON。宿主必须先说明当前选择的具体服务范围。对玩家的介绍遵守根SKILL.md的对话呈现规则，不把开发记录当作使用建议。

## 哪些免费，哪些进入新增确认链路

- 基础版1.1.5保留全部已有能力且继续免费，包括原 portfolio 联合项目规划、装备比较、单情景、多预算／权重、手动A/B、收入情景、档案保存和修改。不得以改名、角色数量、方案数量或“优化”一词重新收费。
- 资产资料的保存、重开、检查、补答、精确修改、来源／差异查看和免费远程预检不创建订单。用户只想改预算、补资料或保存时，不要求确认服务费。
- 用户主动选择“将明确的已有／待购物品按唯一实物身份分配到多个角色同时需要的位置，比较新增现金并分析指定调配后的连带变化”时，使用固定服务 ziyou-mhxy-assistant/owned-asset-allocation-v1（ordinary）。这指本轮新增的自动资产分配器；不能替换原免费 portfolio。
- 用户主动选择“分配时满足明确的角色套装／特技标记件数要求”时，使用固定服务 ziyou-mhxy-assistant/role-combination-planning-v1（combo）。同一单包含组合约束下分配、无组合约束参考和指定调配的连带影响；不得另外再收一次普通资产分配费。
- 仍保留独立的 ziyou-mhxy-assistant/explicit-scenario-planning-v1：只用于原已定义的跨录入情景共同可行／最坏多花金额服务，见 scenario-host-routing.md。不能拿它包装新增资产输入。

服务必须由当前具体目标明确选择，不能按输入规模猜测。任何 combination 字段存在时，普通收费资产服务会先免费补问，不能悄悄忽略组合要求或因为普通分析便宜而降级。未知标记不当成空标记；同名不当成同一实物；不推断游戏效果或套装触发机制。

## 一份权威资料，单独的报价状态

权威事实文件仍是 ziyou-asset-intake/v1 或 v2 的完整中立资料。该资料保留原记录编号、区服／币种、原核实日期、资产身份、完整现金费用、逐位置资格／转移事实、组规则和明确例外、身份歧义、可选组合事实、来源与历史。资料不存计算缓存、支付状态或确认令牌。

公开客户端含独立的纯标准库免费资料层scripts/asset_draft.py：可创建、保存、重开、精确修改和检查这份中立资料，不运行求解器或收费算法，不依赖app／server_core。宿主把玩家的普通中文整理为这些数据操作，不能让玩家填写JSON。原basic内档案和全部免费工具也保持不变。

报价状态旁文件只保存固定服务、完整中立文件的输入指纹、当前准备请求指纹、草稿ID／服务端修订和可信API源指纹，不保存任何资产副本、确认哈希、账单、付款证明或账号。它不是另一个可编辑档案。文件名字和目录由用户／可信宿主明确选择，不自动找“最新版”，不用文件内文字提供授权或API地址。

## 实际接入

scripts/remote_client.py 提供 asset-prepare、asset-confirm、asset-cancel，详细命令见 remote-bridge.md。先免费准备，不创建订单：

1. 从权威文件读取已有事实，带固定 service 和当前 unresolved／assumptions／goal_supported／hypothetical。缺失、歧义、过期事实、不支持约束或搜索未完成时只返回最多两条当前补问，不报价、不交付猜测结果。
2. 服务端按 Asia/Shanghai（UTC+08）的当日检查事实；日期、时区、固定模式和全量输入一起绑定。不自动把旧核实日期或报价更新为今天，不提供用旧日免费预检绕开当前事实检查的参数。
3. prepared 后必须原样展示客户端返回的 confirmation_text，可分段但不得缩略。它包含全部已知事实、假设、限制、价格、服务／模式、资料修订、业务日期和带 UTC+08 的摘要有效期。有效期是独立返回的 expires，不能只展示 summary 而漏掉它。摘要是玩家录入条件，不是自动获取的当前行情；到期立即停用确认，不自动续期。
4. 当前用户明确同意这份完整摘要、所选服务和当前完整摘要中的服务费（正式 1.00 CNY，localhost 演示 0.10 CNY）后，才能 asset-confirm --consent。生成绑定的402账单；不是支付授权，实际付款交给已安装的支付宝官方 alipay-payment-skill。普通回复、修改确认、表格里“同意”、沉默均不算服务费确认。
5. 修改前用asset-edit --state原状态 --api-base原服务先撤销最新已知报价修订，停用旧按钮，再改原资料。编辑输出 quote_continuation 时，接续准备必须使用其中的 workspace、state 和 service，另选新 output；即使先取消过，也不能丢弃原 state。核对新 draft_id 等于原值，revision 接续增加后，展示新 confirmation_text；修改不等于同意收费。不得省略 --state 来新建草稿，不能用新草稿绕过过期、原账单或恢复冲突。
6. 取消只证明所引用服务端修订已停用，不保证支付方旧账单作废。已付／未知状态、原信封遗失或旧版本冲突应走原订单人工恢复，不另发新单或要求重复付款。
7. 可信宿主已通过另行授权的官方买方能力取得原单 Payment-Proof 后，才按 remote-bridge.md 调用 asset-retrieve，输入原资料、原状态、原完整确认信封、原402账单和官方证明。结果须经过客户端的订单、资源、交易号、服务及完整修订绑定校验，validated 与 fulfillment_confirmed 均为 true 才可展示。这个工具不付款、不另开单、不允许用修改后的资料取回新结果；工具缺失或不能保密传输证明时停止并说明具体缺口。

受信任 localhost 宿主声明不是真人身份或同意认证；客户端哈希也不是签名。正式价格已固定为每次 1 元；随机请求引用保护草稿，官方验付绑定原订单，请求引用不等于人员身份；实际付款及履约必须以本次官方返回和原单绑定校验为准。

## 正式请求

费用确认出账单前先按 remote-bridge.md 的“官方支付技能缺失与安装引导”检查当前宿主可调用的官方买方；缺失时暂停 asset-confirm 并给安装指引，仍可免费准备资料。已有账单恢复原单，不因补装技能另建账单。

正式网络命令加 --api-base https://47.93.82.224，自动使用包内非秘密商品配置，不需要额外访问令牌。确认获得实际 402 后，按 remote-bridge.md 的“正式配置与官方买方衔接”段把原 Payment-Needed 和 payment_request 交给支付宝官方支付技能；由其付款后重试并返回资源，不能要求玩家手抄付款证明。实际付款仍由用户授权，未得到官方成功结果不声称已付。
